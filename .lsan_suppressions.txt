# LeakSanitizer suppressions for known/intentional leaks.
#
# Each entry cites a closed bd issue documenting the rationale (file the
# bd before suppressing, close-as-suppressed with the rationale recorded).
# See docs/sanitizer-suppressions.md for the audit + the cross-version
# re-evaluation policy. Kartend-3hjs.1 owns the LSan-side audit.

# CacheDiskStorage's single-thread QThreadPool is intentionally abandoned
# at process exit when drainWithBudget's cooperative-cancel timeout
# elapses (long-running I/O task didn't notice m_cancelToken in time).
# Remove this suppression if cache I/O ever becomes provably strictly
# cancellable. Closed: Kartend-pa5a.
leak:QThreadPool::QThreadPool

# Qt6 GStreamer multimedia backend leaks GstDeviceMonitor and its
# associated GstCaps/GArray/GPtrArray on first QMediaPlayer construction.
# Global caches inside the platform plugin (loaded via
# QPlatformMediaIntegration::instance); freeing them is upstream Qt's
# responsibility. Originally seen on Ubuntu 24.04 / Qt 6.4 / gstreamer
# 1.24. Re-evaluate when CI bumps Qt to >= 6.10 or swaps the GStreamer
# backend. Closed: Kartend-l52j.
leak:gst_device_monitor_new
leak:gst_device_monitor_add_filter
leak:libgstreamermediaplugin.so
leak:QPlatformMediaIntegration::instance

# ScanWorkController's QThreadPool is intentionally abandoned at exit:
# ~QThreadPool() blocks for in-flight scan tasks, and DatabaseManager
# teardown can't afford that wait. Bounded indirect leak (one per
# DatabaseManager construction) — the pool + the cancellation-token
# shared_ptr control block held by m_token. Same pattern as the
# CacheDiskStorage suppression above. Closed: Kartend-dw0j.
leak:ScanWorkController
leak:ScanService::ScanService
